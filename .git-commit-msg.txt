Fix: 安装引擎实测修复 (runCmd 文件重定向 + .env 自动创建 + qr-server .cjs)

实测"全新用户"端到端安装发现的 3 个问题与修复:

1. runCmd 卡死: npm install 的 prepare 钩子 (husky/npx) 派生孙进程继承
   StdoutPipe, cmd.Run() 等孙进程退出导致卡死。改为 stdout/stderr 重定向到
   临时文件 + cmd.Start()/Wait() + tailLogFile 增量读文件。

2. wechat-bot 启动弹交互菜单: 全新 clone 无 .env, cli.js 因 SERVICE_TYPE
   为空进入 inquirer 菜单卡死。startWechat 前 ensureWechatEnv: 无 .env 时
   从 .env.example 复制并写入 SERVICE_TYPE。

3. qr-server ESM 崩溃: 回退到 wechat-bot 目录的 qr-server.js 时, 因包
   "type": "module" 被当 ESM 解析, require 未定义崩溃。面板回退逻辑支持
   qr-server.cjs (wechat-bot 仓库已改 .cjs)。

端到端验证通过: 删三组件 → 一键安装 (clone/npm/astrbot 全成功, 5 阶段
100% 完成) → 服务全部恢复健康。
